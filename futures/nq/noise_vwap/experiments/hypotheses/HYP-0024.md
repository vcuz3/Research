# HYP-0024 — Decision-clock robustness of the continuous-stop baseline

- Status: COMPLETED (EXP-0034). Robustness/sensitivity audit, not an edge claim.
- Created: 2026-07-25
- Origin idea: user asked whether the noise_vwap result is stable to shifting the
  decision clock by 5/10 min and to a 15-min cadence, across the new continuous
  baseline, the 1s first-touch, and the ATR-buffer engines.
- Builder: Claude (Opus 4.8)

## Question / mechanism

The deployed 30-min decision clock has an ARBITRARY phase: decisions on the CLOSE
of 09:59, 10:29, ..., 15:59 ET (the "concretum" `:59/:29` clock), filled next open.
If the edge is real intraday structure it should be stable to (a) shifting that
phase a few minutes and (b) doubling the cadence to 15 min. If a 5-10 min phase
shift swings the headline, the "edge" is pinned to one sampling grid = fragile.

Bands are per-(date, tod) and defined at EVERY minute-of-day, so a clock shift only
changes which tods are entry-decision bars; nothing is rebuilt. The continuous stop
refreshes every bar regardless of the entry clock, so the only thing that moves is
entry timing.

## Exact change

Two variants over the deployed 30-min `:59/:29` clock:
1. Phase shift: decision tods = base +/- {5, 10} min (still 30-min cadence).
2. Cadence: a 15-min decision grid (superset of the 30-min grid).

Each variant run through three exit engines on the identical 1s-covered sample:
E1 1m continuous (close-confirmed, `core/engine.py`, deployed); E2 1s first-touch
(`core/atr_buffer` kernel, k=0); E3 ATR buffer band-1.5*ATR_20 (EXP-0032 best cell).
E2/E3 share one 1.7 GB scan (atr kernel k=0 == first-touch bit-exact).

## Primary metric

Per (engine, clock): zero-eligible-day one-contract daily net Sharpe at 0.5 tick/
side + fees; vol-targeted Sharpe/maxDD; gross/net points per trade; trade count.
The read is DISPERSION across clocks, not the best clock.

## Kill test / decision rule

- ROBUST if every phase shift and the 15m cadence stay net-positive and significant
  (daily t > 2) and the daily-Sharpe deviation from base30 is modest.
- FRAGILE if a 5-10 min phase shift flips the sign, kills significance, or moves
  the headline by a large fraction of the base.
- No Null C: no new edge is proposed; this audits the existing baseline. A Null C
  would only be spent if a shifted clock IMPROVED and were then claimed (it did not;
  base30 is the best phase).

## Controls

- Three independent exit engines sharing the same entries: an entry-timing effect
  must transfer across all three; an exit-engine artifact would not.
- Rule 9a band coverage reported per clock (all clocks >= 99.6% on liquid NQ).
- Common 1s-covered sample (3628 sessions) for all engines and clocks.

## Result

See `artifacts/runs/EXP-0034/review.md`. Directionally ROBUST but magnitude
PHASE-SENSITIVE: every phase and the 15m cadence stays net-positive and significant
(all daily t > 2.0, all vol-tgt Sharpe > 0.81), but base30 is a clear LOCAL OPTIMUM
— every +/-5/10 min shift degrades daily Sharpe by 0.11-0.33 and the +5 min shift is
the worst on all three engines; gross/trade falls on every shift (entry-quality, not
variance). The effect transfers identically across all three exit engines, so it is
a real ENTRY-timing / intraday-seasonality property, not an exit artifact. The 15m
cadence is dilutive (more trades, lower gross/trade, lower zero-day Sharpe) though
vol-targeted Sharpe holds up. Retain the deployed `:59/:29` 30-min clock.
