# HYP-0033 — Mandatory stop as the position-sizing mechanism: deployable risk units and prop-challenge pass rate

- Status: proposed
- Created: 2026-08-11
- Origin idea: none
- Builder: unassigned
- Proposed mechanism: none claimed for alpha. The user's reframing is that a
  compulsory stop is simultaneously the SIZING rule (size = risk budget / stop
  distance), so the risk unit the decision consumes is the stop distance, not the
  session ATR the project has been normalising by. Measuring in the wrong unit can
  reorder variants (LEARNINGS 4: name the object the decision consumes).
- Exact change: none to the strategy. Measurement change only -- express P&L in the
  unit the deployed sizing rule consumes (the stop distance), and simulate the
  challenge with contracts = clamp(floor(budget/(stop_pts*pv)), 1, CAP), CAP in {3,5},
  pv in {MNQ $2, NQ $20}. Engine gains default-off per-trade MAE/MFE tracking and an
  optional intraday causal ATR column for the stop buffer.
- Frozen baseline: EXP-0043 book A (decision-clock stop + require_reset) with the
  EXP-0044 mandatory stop; NQ.
- Primary metric: prop-challenge PASS RATE over every start date ($50k, $3k target,
  $2k trailing DD, $1k daily limit, 250-day horizon), reported for the FULL sample and
  the 2024+ recent regime; plus performance in STOP-BASED risk units
  (R_stop = (points-cost)/stop_distance) alongside ATR units and nominal dollars.
- Kill test: the mandatory stop + stop-based sizing must not be WORSE than the
  project's existing causal vol-target sizing on recent-regime pass rate
  (PROP_CHALLENGE.md: 43% at ~2 MNQ, 24-36% fixed 1-3 MNQ, 2024-26). If the best
  stop-sized cell fails to beat ~36-43% in 2024+, record that the mandatory stop does
  NOT rescue the challenge and that the binding constraint remains the trailing DD,
  rather than presenting the best cell as an improvement.
- Required controls: (1) pass rate over EVERY start date, never a single path -- a
  15-year-profitable strategy always reaches +$3k eventually; (2) width-MATCHED
  intraday-vs-session ATR comparison, else it compares tightness not scale shape;
  (3) per-slot stop-width and stop-out-rate CV (time-of-day selector check,
  LEARNINGS 1); (4) gap-through audit, since a tighter stop is not proportionally
  less risk.
- Data scope: NQ clean Databento 1-min RTH 2011-12..2026-07, 3628 sessions; consumed.
- Multiple-testing note: rolling-start pass rates are HEAVILY OVERLAPPING and not
  independent; 356 starts in 2024+ is ~1.5 years and only a handful of independent
  episodes. Treat as descriptive, wide-error-bar, not a powered estimate.
