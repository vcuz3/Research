# HYP-0031 — require_reset re-entry: blocking same-side re-entry until price returns inside the Noise Area improves risk-adjusted performance

- Status: **rejected for deployment / qualified-positive off-primary** (EXP-0043,
  2026-08-11). Preregistered primary cell (deployed continuous-stop book) is a
  NO-GO on both markets with a valid exposure-matched control. The source spec's
  own configuration (decision-clock stop) PASSES its gate and the decisive
  random-unlock control on both markets (NQ +0.117 frac 0.005; ES +0.224 frac
  0.000) and clears Null C on ES (0.000) while marginally missing on NQ (0.075);
  that cell is SEARCHED, not preregistered, and sits on a stop book this project
  has already superseded. Mechanism: require_reset and the continuous stop are
  SUBSTITUTES. Evidence: `artifacts/runs/EXP-0043/review.md`.
- Created: 2026-08-10
- Origin idea: user-supplied external result (`Require reset rule.md`, an
  independent Noise-Area implementation's "run 18"); the friend reports paired
  improvements in Sharpe, CAGR, drawdown and expected P&L per trade versus the
  `later_decision` re-entry policy.
- Builder: Claude
- Proposed mechanism: after a stop-out the breakout condition is often STILL
  true at the next decision checkpoint (price is still outside the band), so the
  `later_decision` policy immediately re-arms the same side into the same failed
  move. Those re-entries are hypothesised to be lower-quality — the move has
  already been rejected once and the position is being reopened without any new
  information. Requiring price to first travel back INSIDE the Noise Area forces
  a fresh, genuinely new breakout before the same side is retaken, which should
  remove a population of churn trades that pay a round-trip cost for a move that
  has already failed.

- Exact change: a single default-off `reentry` argument on
  `core/engine2.py::simulate_session`/`run`.
  - `"later_decision"` (default) = the current engine, bit-exact.
  - `"require_reset"` = per session, maintain `stopped_side ∈ {0,+1,-1}` and
    `reset_observed ∈ {True,False}` (init `0`, `True`). Evaluation order per
    the spec: (1) if `lower <= close <= upper` set `reset_observed = True`;
    (2) process the stop/flip/exit logic — a STOP exit sets
    `stopped_side = side`, `reset_observed = False` (a flip does not, per the
    spec, and a flip is an opposite-side entry which the rule never blocks);
    (3) a fresh entry on side `S` is permitted only if
    `stopped_side != S or reset_observed`.
  - State resets each session (the spec says the rule "does not affect the
    initial entry of the day"). Reported as a documented choice; a
    carry-across-sessions sensitivity is out of scope for this run.
  - Nothing else changes: same bands (lb90), same 30-min Concretum clock, same
    VWAP entry gate, same band/VWAP stop, same next-open fills, same costs.

- Frozen baseline: the project's deployed NQ continuous-stop baseline —
  `core.session.noise_bands` lb90, RTH, 30-min decision clock, VWAP entry gate,
  every-bar close-confirmed band/VWAP stop, next-open fills, 0.25 tick/side plus
  $2.25/side fees. ES is the transfer market.
  Because the friend's run-18 checks the stop only on the decision clock, the
  study ALSO reports the `exit_check="decision"` book, which is the
  configuration their result was measured on. The deployed continuous-stop book
  is the primary; the decision-clock book is the faithful-to-source secondary.

- Primary metric: full-sample zero-trade-day daily net-ATR-R Sharpe uplift
  (`d_sharpe`) of `require_reset` over the matched `later_decision` book on the
  common post-lookback sample, with total net R as co-primary. Reported for NQ
  (primary market) and ES (transfer).

- Kill test: REJECT unless, on the PRIMARY (deployed continuous-stop) NQ book,
  `d_sharpe >= +0.10` AND `net R >= baseline net R`. Per the standing project
  rule the expensive drift-preserving Null C is spent only if that gate passes.
  A pass must additionally survive:
  (a) the matched-count blocked-re-entry random null below (frac < 0.05), and
  (b) the drift-preserving Null C (frac(null >= real) < 0.05),
  and must TRANSFER in sign to ES, or it is recorded as NQ-specific at best.

- Required controls:
  1. **Matched-count random re-entry drop (the decisive rarity/turnover
     discriminator).** `require_reset` can only ever REMOVE trades, and this
     project has repeatedly found that "fewer trades → higher Sharpe" is
     machinery, not information (EXP-0010 VWAP-touch, EXP-0012 exit band,
     EXP-0016/0017 gap-RVOL, EXP-0026 Hurst, EXP-0018 ES confirmation). The
     matched control must remove an equal number of trades drawn at random from
     the SAME POOL — post-stop same-side re-entry candidates — not from all
     entries, so the comparison isolates WHICH re-entries are blocked rather
     than the fact that re-entries are blocked. Re-run through the stateful
     engine (rule 18), never as a post-hoc trade drop.
  2. **Blocked-trade expectancy (the EXP-0024 diagnostic).** Report the mean
     gross/net R of the trades `require_reset` removes. If the removed trades
     are PROFITABLE, the rule fails inverted regardless of the Sharpe number.
  3. **Gross-per-trade on the kept trades.** Rising gross/trade = real per-trade
     quality selection; flat/falling = pure exposure reduction.
  4. **Reset-cadence sensitivity.** The spec recognises a reset only at decision
     checkpoints; the deployed book checks stops every bar. Run reset detection
     on both cadences — if the result depends on the cadence, it is a clock
     artifact, not the rule.
  5. **ES transfer** (the sibling-market mechanism test).
  6. Drift-preserving Null C (`core/nulls.py::null_c_returns` via
     `_null_c_frame`), gated on the primary metric.

- Data scope: NQ and ES clean Databento 1-minute RTH, 2011-12 .. 2026-07, common
  post-lb90 sample. Consumed history — no sealed holdout is available (rule 26).

- Multiple-testing note: the rule itself has NO free parameters, which is its
  main appeal versus the swept families this project has rejected. The only
  searched axes are the 2 stop books × 2 reset cadences × 2 instruments = 8
  cells, all reported. The primary cell (deployed continuous-stop book, NQ,
  every-bar reset) is declared here in advance; the others are robustness
  reads, not candidates for selection.

## Rationale and evidence

The external result is a paired comparison inside another codebase whose
baseline differs from this project's on several load-bearing points (60-session
lookback vs 90, vol-target sizing with a 4x leverage cap vs 1 contract,
decision-clock stop vs continuous stop, `indicative_ratio` price treatment).
Those differences mean the friend's Sharpe/CAGR/drawdown numbers cannot be
imported; only the RULE transfers. This run therefore tests the rule as a
single-variable change on this project's audited engine and frozen baseline.

Prior expectation is guarded. The rule's stated effects — "reduces repeated
same-day re-entries, reduces churn, lowers cost drag, reduces trade count" —
are exactly the signature this project has five times shown to be a
turnover/capacity lever rather than alpha. The control that decides it is
control 1: whether blocking THESE re-entries beats blocking a random equal
number of the same kind of re-entry.
