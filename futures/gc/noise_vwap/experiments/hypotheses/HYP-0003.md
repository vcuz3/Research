# HYP-0003 — Continuous (every-bar) stop transfers the NQ GO uplift to GC

- Status: REJECTED (EXP-0004, 2026-07-19) — the NQ GO result inverts on GC: every-bar
  stop collapses gross +0.359→+0.127 pt/trade and net Sharpe +0.46→−0.06. See
  `artifacts/runs/EXP-0004/review.md`.
- Created: 2026-07-19
- Origin idea: IDEA_BACKLOG "Continuous (every-bar) stop"
- Builder: claude
- Proposed mechanism: The frozen GC baseline only *checks* its band/VWAP stop on
  the 30-min Concretum decision clock. Between clock ticks a losing position can
  run well past its stop level and is only exited at the next :29/:59, giving back
  drift. On NQ, moving the stop check to **every 1-min bar** (entries/flips still
  on the decision clock) was the single strongest Null-C survivor: Sharpe
  1.16→1.30, t 3.26→3.65 at the *same* gross profit, Null-C z5.20 / 28% capture.
  The uplift is variance reduction from cutting losers sooner, not extra gross —
  so it should transfer to any instrument where losers overshoot the clock,
  including GC, IF the effect is real timing and not machinery.
- Exact change: one variable — `exit_check="decision"` → `exit_check="every_bar"`
  in `core.engine.run`. Entries, flips, VWAP gate, band construction, decision
  clock (30-min Concretum :29/:59), lookback=90, next-open fills, cost grid: ALL
  held at the frozen baseline. `noise_bands` already emits a band at every tod, so
  the every-bar branch checks `max(band,vwap)`/`min(band,vwap)` each minute with no
  other change. No new parameter is introduced or searched (single pre-specified
  variant, not a grid) → no multiple-testing inflation.
- Frozen baseline: `reports/BASELINE.md` / EXP-0000 (decision-clock stop): gross
  +0.359 pt/trade, net +0.214 @0.50tick, day$net +30.2, net t=+1.25, net Sharpe
  0.46; 2641 trades. Run command
  `python -m futures.gc.noise_vwap.scripts.run_baseline GC 90`.
- Primary metric: per-day-clustered **net daily Sharpe** and **net day-$ t-stat**
  at 0.50 tick/side, decision-clock baseline vs every-bar, on the identical date
  set. Report gross too (rule 20): the NQ claim is same-gross / higher-Sharpe, so
  gross must NOT materially rise — a gross jump would signal the every-bar stop is
  manufacturing fills, not cutting losers.
- Kill test (declared before the run): REJECT the transfer if the every-bar stop
  does **not** raise net daily Sharpe over the decision-clock baseline by a
  meaningful margin (target ≥ +0.05 Sharpe, matching the NQ effect size), OR if it
  raises Sharpe only by *inflating gross* (gross pt/trade up materially) rather
  than cutting loser variance, OR if the uplift does not survive a claim-matched
  Null-C (real Sharpe-uplift within the path-preserving noise distribution). A
  lower or equal Sharpe is a clean NO-GO; do not tune the clock to rescue it
  (Rule 26, consumed history).
- Required controls: (1) gross vs net decomposition (is the uplift variance
  reduction or new gross?); (2) reason-code / loser-tail comparison (every-bar
  should cut the left tail of losers, shortening `stop` exits); (3) claim-matched
  Null-C on the *uplift* (port `core/nulls.py`), gated on the real pass first
  clearing the Sharpe target — do NOT spend the null if the real pass fails
  (memory: gate-nullc-on-success-metric).
- Data scope: GC RTH 2011-08-01..2026-07-16, `data/GC_1m_clean.parquet`, 2641-trade
  baseline date set. Consumed history — only a future shadow is a clean holdout.
- Multiple-testing note: a single pre-specified variant ported from an already-
  validated NQ result; no parameter search. Confirmatory, not exploratory.

## Rationale and evidence

NQ evidence: memory `nq-noise-vwap-momentum` / project `STUDIES.md` — continuous
stop is the strongest Null-C survivor of the NQ exit studies (z5.20, 28% capture,
faithful-config Null-C re-run done), robust on clean Databento data (clk30ebar
z5.68 / 22%). It is already an *adopted* NQ change. Porting it to GC is a direct
transfer test of a GO result, the natural first move after the tuning-grid
(HYP-0002) rejection: it changes exit *timing granularity*, not the searched
parameter space, so it does not re-consume the band-k/lookback/anchor grid.

Prior expectation is guarded: GC's edge is real-but-tiny and cost-fragile, and
the sizing verdict (Sharpe 0.07) is unlikely to move on a variance-reduction tweak
alone. This tests whether the *per-trade* timing quality improves as it did on NQ,
not whether GC becomes deployable standalone (it is already NO-GO; a positive
result feeds the portfolio-leg idea, not a standalone reversal).
